# 0003: Browser wire captures are the evidence

- Status: Accepted; amended 2026-10-26 by [0035](0035-version-policy-and-capture-inheritance.md) (evidence class inherited)
- Date: 2026-10-21

## Problem

Fingerprint claims are easy to copy and hard to check. Other clients'
presets, blog posts and even browser source disagree with what browsers
send.

## Decision

Evidence ranks: a real browser's wire capture against our capture server,
stable across samples (and scenarios) > browser source > other clients
(leads only). Every profile claim is recorded with its evidence class and
the test that keeps it true in [`profiles/EVIDENCE.md`](../../profiles/EVIDENCE.md);
classes are wire, wire across scenarios, fitted (a rule verified byte for
byte against traces), measured on another request kind, copied, and
inherited (see the amendment).

Profile data that can be derived from captures is generated by tools
(`internal/harness/cmd/hellogen`, `h3gen` and `kindsgen`), not hand-edited, and the tools
refuse captures they cannot reconcile. End-to-end tests replay mimicry
against the same server and compare with the browser's traces.

## Evidence

The rule has paid for itself repeatedly: httpcloak's single joined Safari
cookie field contradicts every Safari 27 sample; deriving the kinds data
found that header order varies within a kind (0006) and that Firefox's CSS
fonts differ from its `FontFace` loads, both missed when reading the
captures by eye.

## Consequences

Captures take real browsers on real machines (Safari needs macOS), and run
in the foreground. A finding that cannot be measured is recorded as a gap,
not guessed (0008).

## Revisit when

Never for the ranking; the capture setup can change.

## Amendment 2026-10-26: inherited evidence

A new version may take a scenario's captures from an earlier version
(`capturesFrom`): its claims there are class **I**, inherited, checked
against the earlier version's captures until its own are taken
([0035](0035-version-policy-and-capture-inheritance.md)).
