# Deriving a profile

## Built-in profiles

- A built-in profile is a JSON file in `profiles/data/`.
- Its accessors are generated by `cmd/profilegen` (`go generate ./profiles`).
- Every built-in profile must pass `profile.Parse`. Two checks enforce it:
  - The generator refuses to generate from an invalid file. `TestGeneratedFileUpToDate` in `cmd/profilegen` runs it over every file.
  - Every e2e run loads each built-in through `profiles.ByName`, which parses it (`TestCapturesFromNamesCapturedScenarios`).
- Captures record one connection and are not complete profiles. So the harness loads them with `profile.Decode`.
- A profile without a matching capture in `testdata/captures/` is not finished.

## A new version

- A new version starts as a copy of the previous one ([decision 0004](../decisions/0004-complete-profile-files.md)).
- Replace every captured field from the new capture.
- Some copied fields cannot be shown by a capture: `http2.hpack`, header slots, `cookies` and `http1` slots.
  Treat them as unverified until the e2e tests pass against the new traces.
- `cmd/refresh` does the copy, sets `capturesFrom` and runs the generators below.

## The generators

Sections derived from captures are regenerated, never hand-edited.

- Run the three generators in this order:
  1. `go run ./cmd/hellogen`: the ClientHello's shape and the fields in [hellogen](#hellogen).
  2. `go run ./cmd/h3gen`: `quic`, and `http3` but for kindsgen's header lists and priorities ([h3gen](#h3gen)).
  3. `go run ./cmd/kindsgen`: the profile's `kinds`, `context`, navigation `variants`, `emptyBody`, `clientHints` and `urls`, from the captures listed [below](#kindsgen).
- Run each with `-profile ../../profiles/data/<name>.json`.
- Each refuses a sample its rule does not describe.
- Each generator has its own `TestRegenerateReproducesProfiles`.
  It fails while a committed profile differs from what the generator derives from the committed captures.
- `go generate ./profiles` refreshes the accessors afterwards.

### Captures each generator reads

- hellogen and h3gen read the edge captures too.
  - The edge captures are `server.H3EdgeCaptures`: `h3-blackhole`, `h3-broken`, `h3-vn`, `h3-download`, `h3-early`, `h3-too-early` and `h3-streams-blocked`.
- kindsgen reads only `h3-discovery` and `h3-page` (`server.H3ProfileCaptures`).

### hellogen

hellogen derives the ClientHello's shape and the fields below.
Each field gives what it records, then **From:** (the captures), then **Without the captures:** and **Decision:** where they apply.

- `http2.openingRecords`: how the browser cuts a new HTTP/2 connection's opening into TLS records.
  - **From:** every connection whose first request was waiting as it opened. Testing-build captures are included.
  - **Decision:** 0042.
- `http2.goawayReply`: the GOAWAY sent on the server's.
  - **From:** every HTTP/2 connection the capture server sent GOAWAY on.
- `tls.quic`: the QUIC ClientHello.
  - **From:** every h3 connection's hello.
- `tls.quic.versionNegotiation`: Firefox's other hello after Version Negotiation.
  - **From:** the `h3-vn` captures.
- `tls.quic.earlyDataBefore`
  - **From:** every resumed QUIC hello of the edge captures. hellogen checks each of them.
- `tls.websocketH1`
  - **From:** the `websocket` capture.
- `tls.helloRetry`: where the hello sent again after a HelloRetryRequest puts the cookie.
  - **From:** every retried connection of the `hrr` capture.
  - **Without the captures:** left out, not measured.
- `tls.realEch`: what the browser sends to a host whose HTTPS record carries an ECH config. It covers:
  - the config and suite it took;
  - the inner hello and its padding;
  - the outer hello of a resumed inner one;
  - what follows a rejection;
  - a list that does not parse.
  - **From:** every connection of the `ech` capture. Samples must agree but for `echGaps`.
  - **Without the captures:** left out, not measured.
- `tls.realEch.altSvcIgnored`
  - **From:** the `ech-h3` capture.
  - **Without the captures:** left out, not measured.
- `http1.uploadRecords`: how the browser cuts an HTTP/1.1 request with a body into TLS records.
  - **From:** every request of the `http1-upload` capture. Testing-build captures are included.
  - **Decision:** 0052.
- `tls.trailingDotSni`: the server_name of a host ending in a dot.
  `keep` when the server refused a ClientHello naming it with its dot.
  `omit` when the request came with no SNI.
  - **From:** the `urls` capture's `h-dot` case, fetched and navigated to.
  - **Decision:** 0057.
- `tls.clientAuth`: how the browser answers a CertificateRequest.
  - The CertificateVerify scheme per TLS version and key type. Samples must agree.
  - `resume`: a later connection offered to resume a session the certificate went in.
  - `restart`: per sample, no first connection to a host answered the request, a later one carried it, and no connection answered with an empty Certificate. Samples must agree.
  - **From:** every connection of the four `client-cert-*` captures.
  - **Without the captures:** left out.
  - **Decision:** 0064.
- `proxy.https`: how the browser uses an `https://` proxy.
  - The HTTP/2 CONNECT's fields and its HEADERS weight.
  - The code that resets a tunnel's stream.
  - Whether TLS to the proxy resumes, over HTTP/1.1. True when at least half of each sample's later tunnel connections resumed. False when at most a quarter did.
  - It refuses hellos to the proxy that are not the profile's, and HTTP/2 openings that are not its `http2` section's.
  - It refuses HTTP/1.1 CONNECTs that are not `proxy.connect`'s, and tunnels that contradict `proxy.connectNoResume`.
  - **From:** the four `proxy-https*` captures.
  - **Without the captures:** left out.
  - **Decision:** 0065.
- `proxy.socks4`: every request is a SOCKS4 CONNECT with an empty user ID.
  - Through `proxy-socks4`: a resolved IPv4 address alone.
  - Through `proxy-socks4a`: SOCKS4A's `0.0.0.x` and the host name (`hostname` true).
  - **From:** the `proxy-socks4` and `proxy-socks4a` captures.
  - **Without the captures:** left out.
  - **Decision:** 0063.

### h3gen

- h3gen derives `quic`, and `http3` but for kindsgen's header lists and priorities.
- It checks every value against every connection.
- It pins the few samples that differ in `sampleGaps`.

#### From the edge captures

- `quic.loss`: probes, give-ups, abandon closes, path degrading.
- `quic.keepAlive`, `quic.ack`, `quic.credit`, `quic.keyUpdate` and `quic.versionNegotiation`.
- `quic.streamsBlocked`: left out, not measured, for a profile without an `h3-streams-blocked` capture.
  Every other edge capture is required.
- `http3.discovery.fallback`.
- `http3.earlyData`: which methods go in 0-RTT, where a held request leaves, and the retry after 425.
- `http3.earlyStreamsWithRequest`: the handshake streams in the 0-RTT request's packet.
- `http3.closeOnGoaway`: the browser closes a connection the server sent GOAWAY on. Also from `h3-discovery`.
- `http3.discovery.dialDelayMs` and `resumedDialDelayMs`: how long after the request that waits for it a fresh or resumed dial starts.
- `quic.zeroRtt`: from the resumed connections of both sets.
  Where the h3 captures have none (Safari), it holds the edge captures' resumed first flights to the full handshakes' rules.

#### From h3-resume-table

From `h3-resume-table` alone (`server.H3ResumeTableCaptures`), h3gen derives `http3.qpack.resumed`.

- A resumed connection's encoder stream must open with the server's capacity, in 0-RTT on at least one connection.
- Every connection whose encoder wrote again in 1-RTT must agree on whether the capacity was set a second time there:
  - set again: `remembered_repeat` (Chrome and Edge);
  - not set again: `remembered` (Firefox).
- Without the capture it stays unset.

### kindsgen

kindsgen's captures, and what each gives the profile:

- `<name>.kinds.pagetrace.json.gz` and `<name>.kinds-http1.pagetrace.json.gz`: every kind over HTTP/2 and HTTP/1.1, and the context rules.
- `<name>.kinds-plain.pagetrace.json.gz`: the non-secure variants.
- `<name>.cors.pagetrace.json.gz`:
  - `context.preflightCache`;
  - the cors page's fetches, merged into the Fetch kind: its PUT variants, and cross-site fetches with and without a header the page set (the `pageSet` condition).
- `<name>.cookies.pagetrace.json.gz`:
  - the cross-site form POST navigation variant (`c-nav-post.so`);
  - the image and injected_image `{same-site, redirected, crossOriginRedirect}` variants;
  - slots its requests add (Safari 27's `cookie` on a redirected same-origin image).
- `<name>.cors-edge.pagetrace.json.gz`: fetch redirects merged into the Fetch kind.
  - PUT/DELETE hops, the GET hops of 303s and POSTs, a same-origin chain, a cross-site hop within its origin.
  - Every redirect's request takes its `crossOriginRedirect`, `originBeforeRedirect`, `methodChangedByRedirect` and `insecureBeforeRedirect` conditions from the captured request it follows.
- `<name>.redirects2.pagetrace.json.gz`: redirects of every kind (`redir-<kind>`).
  - Images, crossorigin scripts, XHR, fetch() methods and their PATCH preflights, form POSTs and the navigation chain.
  - Chrome's error-page reload is left out.
- `<name>.nav-redirect-*.pagetrace.json.gz` (any number, optional): navigations whose start URL `/p/<label>` redirects to `/p/<label>.hop<n>`.
  Each goes over HTTP/2 or plain HTTP/1.1: typed ones and a page's.
  - Typed ones: no Referer. Their requests take `site: none`.
  - A page's (`nav-redirect-page`, `nav-redirect-form`, `nav-redirect-click`): the label's sites.
  - A clicked navigation (`nav-redirect-click`) is grouped with the script's of its condition. So its variant gains the `sec-fetch-user` slot. Their orders must merge.
  - A request one sample sent in a form no condition explains (browser state) is left out only if pinned in `sampleGaps` with why.
  - A pinned one missing from its capture is an error.
- The cookie twins (decision 0048, optional): `<name>.cors-edge-cookies`, `<name>.redirects2-cookies` and `<name>.nav-redirect-*-cookies`.
  - Each is its original with cookies set on the hosts its hops go to.
  - Their requests are read with their original's and grouped by the same conditions.
  - So a hop variant gains the `cookie` slot where the twin's hops carried cookies. Their orders must merge.
- `<name>.headers-order.pagetrace.json.gz`: `context.headerTable`, and fetch/XHR requests with headers the page set.
- `<name>.websocket.pagetrace.json.gz` and `<name>.websocket-h2.pagetrace.json.gz`: the `websocket` kind.
  - Handshakes over HTTP/1.1.
  - Handshakes as HTTP/2 extended CONNECTs, whose `:protocol` must follow `http2.pseudoHeaderOrder`.
  - `ws://` from the plain page, as its `insecure` variant.
- `<name>.h3-discovery*.pagetrace.json.gz` and `<name>.h3-page*.pagetrace.json.gz` (unforced and `.local-roots`):
  - `http3.headers`: each kind's HTTP/3 list against its HTTP/2 one (Firefox's pseudo-header order, dropped `te`, `alt-used` placement);
  - `http3.high`/`http3.low`: priorities measured only over HTTP/3;
  - the `kinds.xhr` POST variant;
  - Safari's `injected_image.low`, from its `h3-page` requests over HTTP/2.
  - A layout-driven priority is pinned in `h3PriorityGaps`.
- `<name>.bodiless*.pagetrace.json.gz`: `emptyBody` on the navigation (the form POST) and `kinds.fetch` (`deriveEmptyBodies`).
  - The methods sending `content-length: 0` with no body.
  - Its place: the list's, or last before `te`.
  - Over HTTP/2, an empty DATA frame ending the stream.
  - Samples, methods and HTTP/3 must agree.
  - Without the capture both stay unset.
- `<name>.client-hints*.pagetrace.json.gz`: `clientHints` (`deriveClientHints`).
  - The hints and order of the navigation after the opt-in to every hint.
  - The header a restart's hints follow.
  - The full version and the machine's values (`downlink` the centre of every value sent).
  - `tableOrder`: Blink's order of entry, which must reproduce every captured subresource's run.
  - Every captured request's hints must be what the model sends.
  - Without the capture, or where no hint beyond the lists was sent (Firefox, Safari), it stays unset.
- `<name>.urls.pagetrace.json.gz`: `urls` (`deriveURLs`).
  - `pathEncodes`: the characters the browser encodes in a path beyond the set every browser does.
  - `checkPunycode`: whether it refuses the malformed punycode host.
  - Samples, and each case's fetch and navigation, must agree.
  - A character the shared set encodes may not go as written.
  - Without the capture it stays unset.
  - hellogen reads the same capture for `tls.trailingDotSni`.

### Variants measured over HTTP/2 only

- A variant only the cors, cors-edge or cookies capture shows was measured over HTTP/2 only.
  So it has no `http1` list, and mimicry refuses such a request over HTTP/1.1 (`ErrNotMeasured`).
- Rerun kindsgen after recapturing any of these.
- `TestKindsMatchBrowserTraces` checks the result against the same traces.
