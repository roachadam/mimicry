# CORS preflights: what Chrome 155, Firefox 158 and Safari 27/26 send, 2026-10-24

Two sources:
- the preflights already in the `kinds`, `kinds-http1` and `kinds-plain`
  captures: four per sample (`fetch-json` and `fetch-custom`, to the
  same-site and the cross-site host);
- the new `cors` scenario. From `https://www.kinds-a.test`, the page makes
  its fetches to `https://cdn.kinds-b.test` in order (`server.CORSSteps`),
  over HTTP/2.

Three samples per browser, Safari 26 on the second Mac. Every browser's
three samples were identical.

|---|---|---|---|

| `accept` | `*/*` | `*/*` | `*/*` |
| priority, weight | as `fetch()`: `u=1, i`, 219 | as `fetch()`: `u=4`, 21 | as `fetch()`: `u=3, i`, none |
| Cookies | never, even for `credentials: "include"` | never | never |
| Connection | the credential-less one (the request with cookies goes on another) | the same one as the requests | the same one |

The HTTP/1.1 and plain-HTTP lists are in the profiles (`kinds.preflight`)
and match the requests line for line.

## The cors page, step by step

What each browser sent, per step. "OPTIONS" means a preflight, then the
request. Empty cells match the cell to their left.

| Step | Chrome | Firefox | Safari 27, 26 |
|---|---|---|---|
| `multi.cs`: headers `X-B`, `X-A` | OPTIONS, `Access-Control-Request-Headers: x-a,x-b` | | |
| `put.cs`: `PUT` | OPTIONS, `Access-Control-Request-Method: PUT`, no `-Headers` | | |
| `include.cs`: credentials include, `X-Mimicry` | OPTIONS without cookies; the request with | | |
| `maxage.cs` (Max-Age 600), `X-Mimicry` | OPTIONS | | |
| the same again | cached | | |
| `X-Other` | OPTIONS | | |
| `X-Mimicry` again | **OPTIONS** | **cached** | **OPTIONS** |
| `PUT` with `X-Mimicry` | cached | | |
| `default.cs` (no Max-Age) | OPTIONS | | |
| the same at once | cached | | |
| the same after 6 s | OPTIONS | | |
| `denied-headers.cs`: no `Access-Control-Allow-Headers` | OPTIONS only: **no request** | | |
| `denied-status.cs`: preflight answered 403 | OPTIONS only: **no request** | | |
| `redirect.cs`: answered 307 to `redirect-target.cs` | OPTIONS, request, OPTIONS for the target, request | | |

So:
- the default lifetime is 5 s, as the Fetch standard says: cached at once,
  expired by 6 s;
- Max-Age is honoured, at least to 600;
- Chrome and Safari remember one answer per URL, the latest. After the
  `X-Other` answer, `X-Mimicry` is no longer allowed and needs a new
  preflight. That answer listed `GET, POST, PUT`, so the `PUT` then goes
  through.
- Firefox merges answers: `X-Mimicry`, allowed by the first answer, stays
  allowed.

The step after `X-Other` was added for this distinction. Without it, a
cache "per request" and "replace per URL" explain Chrome's and Safari's
traffic equally well.

## Not measured

- Max-Age caps. Browser source gives Chrome 2 h, Firefox 24 h, Safari
  10 min, as leads only. mimicry honours Max-Age as sent.
- Whether Chrome keys its cache by top-level site (network isolation).
- Preflights for requests from a cross-site frame.
