# TLS session resumption in Chrome 155, Firefox 158 and Safari 27, 2026-10-24

The `resume` scenario: a page whose every response closes its connection
(HTTP/1.1 `Connection: close`, HTTP/2 `GOAWAY`), so each of its requests,
300 ms apart, opens a new connection while the browser holds the ticket the
last one received: three to the page's host and two to a same-site host
over HTTP/2, two to an HTTP/1.1-only host, then three together to that
host. The server (Go's TLS 1.3) issues one ticket per connection. Each
connection's whole ClientHello is recorded, with how many tickets it
offered, a hash of the first, and whether the server resumed. Three
samples per browser.

## Who resumes

| | Chrome | Firefox | Safari |
|---|---|---|---|
| Sequential new connections | resumed, one ticket each | resumed, one ticket each | **never**, not once in 36 connections |
| Ticket reuse | never: every resumption offers a different ticket | never | — |
| Three parallel connections | one resumes, two full handshakes | the same | — |
| 0-RTT (`early_data`) | not offered | not offered | — |
| Server accepted | always | always | — |

Chrome's second connection to the page's host was a full handshake in two
samples of three: the page's first connection closed right after its
response, and Chrome had not yet taken the ticket. Every later one resumed.

Earlier captures agree: Chrome and Firefox resumed some later connections
on the kinds pages; Safari none.

## The resumed ClientHello

| | Chrome | Firefox |
|---|---|---|
| Extensions | the full hello's, freshly shuffled, plus `pre_shared_key` last (after the trailing GREASE) | the full hello's in the same order, **without `session_ticket`**, plus `pre_shared_key` last |
| Everything else (suites, groups, key shares, GREASE payloads) | unchanged | unchanged |

## From a TLS 1.2-only server (`resume-tls12`)

The same page, the server capped at TLS 1.2 (Go's, which resumes by
session ticket and issues a new ticket on every handshake, resumed ones
included). Connections that carried no request (Chrome sometimes opens a
spare one to the page's host during navigation) are counted apart.

| | Chrome | Firefox | Safari |
|---|---|---|---|
| Sequential new connections | every one resumed, each with the newest ticket | **alternate**: resumed, full, resumed, ... | never |
| Three parallel connections | **all three resume, with the same ticket** | all three full (the ticket was used, none kept from the resumed one) | — |
| Resumed ClientHello | the full hello, the ticket in `session_ticket`; no `pre_shared_key` | the same | — |

So TLS 1.2 tickets are reusable for Chrome (unlike its TLS 1.3 ones), and
single-use for Firefox, which also keeps no ticket a resumed connection
receives.
